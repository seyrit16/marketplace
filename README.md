# Marketplace — микроcервисный маркетплейс  

**Marketplace** — pet-проект маркетплейса с микросервисной архитектурой на базе Spring Boot и Java 17.  

## Что это за проект  

- Проект включает **5 независимых микросервисов**, каждый со своей бизнес-логикой, собственной базой данных и API.  
- Основные роли пользователей: **покупатель**, **продавец**, **оператор ПВЗ**.  
- Цель — имитация базовой платформы e-commerce / маркетплейса с разделением ответственности, распределёнными сервисами и устойчивой архитектурой.  

## Технологический стек  

**Backend / язык / фреймворки**:  
- Java 17  
- Spring Boot 3.4.x  
- Maven  

**Компоненты / инфраструктура**:  
- PostgreSQL — отдельная база для каждого микросервиса  
- Redis — для кодов авторизации (TTL 5 мин), кэширования корзины (TTL 7 дней)  
- Elasticsearch — полнотекстовый поиск по товарам + фильтрация  
- Apache Kafka — асинхронное взаимодействие между сервисами  
- Spring Cloud OpenFeign — синхронные HTTP-вызовы между сервисами  
- JWT (JJWT) — авторизация / аутентификация  
- MapStruct, Lombok, Bean Validation  

**Безопасность и вспомогательные функции**:  
- Email-уведомления (через Gmail SMTP)  
- Локальное файловое хранилище для изображений товаров (до 10MB)  
- Docker + Docker Compose — контейнеризация и локальное развёртывание всех сервисов  

## Возможности (функционал)  

- Регистрация / авторизация пользователей (покупатель / продавец / оператор)  
- Добавление, редактирование, удаление и просмотр товаров (продавцами)  
- Поиск и фильтрация товаров (по названию, описанию и параметрам) — via Elasticsearch  
- Работа с корзиной: кэширование (Redis), хранение временного состояния  
- Создание заказов, оформление покупки  
- Возможность обработки заказов оператором — для роли «оператор ПВЗ»  
- Отправка уведомлений пользователям (на email) при событиях (например, успешный заказ)  
- Хранение изображений товаров локально, с ограничением на размер загружаемых файлов

## Архитектура / структура

* Каждый микросервис имеет собственный модуль, базу данных и отдельные настройки.
* Сервисы общаются между собой через HTTP (Feign) и через асинхронные сообщения (Kafka).
* Разделение ответственности: каталоги для контроллеров, сервисов, репозиториев, DTO, мапперов.
* Использование DTO + MapStruct + валидации для защиты данных и чистой архитектуры.
